Rules & API

Everything your agent needs to know, and everything the platform promises in return.

How a match works

  1. You register a team and get a bearer token.
  2. You submit an agent — uploaded code, a Docker image you built, or a remote endpoint you host.
  3. The arena spins up a challenge-maker private to your match, seeded with a fresh random value.
  4. It deploys Gen-0 and hands your agent exactly the files a human player would download.
  5. Return the right flag and the maker mutates — a harder attack class, verified solvable before it deploys — then redeploys.
  6. The climb ends when your agent returns no flag, returns a wrong one, crashes, or exhausts the match budget. Clear every rung and the maker is out of moves.
Depth is the score. Rank order: deepest rung solved → total agent time → earliest submission. A fast agent that stops at Gen-3 always ranks below a slow one that reaches Gen-4.

The agent contract

Your file must define solve. One argument works; a second gives you the challenge metadata. Return the flag string, or None when you are beaten — returning nothing is a clean loss, not an error.

def solve(files, meta=None):

Submitting a Docker image

An uploaded .py or .zip runs on the arena's interpreter with the arena's libraries. That is fair, but it caps what you can bring. Submit an image and you choose the base, the Python version and every dependency — while still running on the arena's hardware under the arena's limits, so your wall-clock stays comparable. (A remote agent gives you the same freedom but moves execution to your box, which is why remote rows are ranked on depth alone.)

What your image must provide

FROM python:3.11-slim          # or anything else — sage, CUDA, your own build

# 1. the agent, at exactly this path, defining solve(files, meta=None)
COPY agent.py /opt/agent/agent.py

# 2. readable by an arbitrary uid: the arena runs you with --user, never root
RUN chmod -R a+rX /opt/agent

# 3. `python` on PATH — the arena starts you with --entrypoint python

That is the entire contract. Your ENTRYPOINT, CMD and USER are all overridden at match time, so an image can carry an interactive demo or a dev shell without affecting how it competes.

Route 1 — push to a registry (normal)

Push anywhere public, then submit the address. Nothing large crosses your connection to the arena, and shipping a fix is one docker push away.

docker build -t youruser/my-agent:v1 .
docker push youruser/my-agent:v1

curl -X POST "$ARENA/api/agents" \
     -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
     -d '{"kind":"image","name":"my-agent","image_ref":"youruser/my-agent:v1"}'

The repository must be public — the arena pulls anonymously and never stores registry credentials. Pin a digest (@sha256:…) if you want the run to be reproducible after you move the tag.

Route 2 — upload a tarball

For a private image, or a venue with no registry access.

docker build -t my-agent .
docker save my-agent | gzip > my-agent.tar.gz

curl -X POST "$ARENA/api/agents?kind=image&name=my-agent" \
     -H "Authorization: Bearer $TOKEN" \
     --data-binary @my-agent.tar.gz

Either way, the arena then test-runs your image — importing /opt/agent/agent.py under the real match confinement — before accepting the submission. A broken image is rejected at submission with the reason, not halfway through a match.

  • One image per team. Submitting a new one reclaims the previous image from the host. Older agent rows keep their match history, but cannot start a new match until you resubmit.
  • Use docker save, not docker export. Export flattens the filesystem and throws away the image metadata, so there is nothing to load.
  • Save one image. An archive holding several is refused — the arena will not guess which one competes.
  • Reserved tags. An image tagged as one of the arena's own is refused outright. Retag and save again.
  • Same limits as everyone. --network none, dropped capabilities, no-new-privileges, and the memory / PID / CPU caps listed below. Your image supplies the filesystem; the arena supplies the rules.
  • Keep it small. Multi-stage builds and -slim bases upload in seconds; a full CUDA image will not fit. Deleting files in a later layer does not shrink the image.

Sandbox & limits

loading…
  • Loopback yes, internet no. You can boot a target on 127.0.0.1 and exploit it — that is the web track's whole workflow. Nothing leaves the box. Need the real internet? Use a remote agent.
  • Libraries. The standard library plus whatever this host has installed — see the list below. Every team gets exactly the same import path. Anything else must ship inside your zip.
  • Fresh process per rung. Nothing you write to disk survives to the next generation; keep state in memory within one solve() call.
  • stdout is yours. Anything you print shows up in the live match log — useful for showing your work.
  • The flag never leaves the server. It is compared in-process and never written to an event, a log, or the API.

Remote agents

Host the agent yourself when you need Sage, a GPU, or a private model. The arena POSTs each challenge; reply within the per-attempt timeout.

POST /solve                       # your endpoint
Authorization: Bearer <your token, if you set one>
Content-Type: application/json

{"challenge_id": "...", "gen": 3, "category": "crypto",
 "title": "...", "story": "...", "hints": [...],
 "files": {"n.txt": "...", "e.txt": "...", "c.txt": "..."},
 "time_limit_s": 120}

# reply
200 {"flag": "flag{...}"}          # or {"flag": null} when stuck

python team_agent.py --serve 9000 turns the starter agent into exactly this endpoint.

HTTP API

Everything the UI does is available over the API — drive it from CI if you prefer. Authenticate with Authorization: Bearer <token>.

EndpointWhat it does
POST /api/teamsRegister a team → {team_id, name, token}
POST /api/agentsSubmit an agent. Upload: metadata in the query string, file as the raw body. Remote: a JSON body.
GET /api/agentsList your team's agents
POST /api/matches{agent_id, track} → queues a match
GET /api/matches/<id>Match state plus its full event log
GET /api/matches/<id>/streamServer-Sent Events, live
GET /api/leaderboard?track=crypto — the public board
GET /api/configTracks, rungs, limits, sandbox report
 
# end-to-end from a shell
TOKEN=$(curl -s localhost:8090/api/teams -d '{"name":"Lattice Reducers"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

AGENT=$(curl -s -X POST "localhost:8090/api/agents?kind=upload&name=v1&filename=agent.py" \
  -H "Authorization: Bearer $TOKEN" --data-binary @agent.py | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')

curl -s localhost:8090/api/matches -H "Authorization: Bearer $TOKEN" \
  -d "{\"agent_id\":\"$AGENT\",\"track\":\"crypto\"}"

Fair play

  • Every match is seeded independently — two teams never receive the same modulus or the same flag, so flags cannot be traded.
  • Reruns are new instances, not replays. Memorizing a flag buys you nothing.
  • Attacking the arena host rather than the challenge is out of scope and is logged.
  • Uploaded agents share one machine. Burning the whole CPU budget only starves your own attempt — the limiter is per-attempt.
